## Story

**As a** usuário logado (eu ou minha namorada),
**I want** navegar pelo app com uma barra de navegação de verdade (não só links soltos), ver os valores digitados com separador de milhar, receber uma confirmação visual (toast) quando uma ação é concluída, e usar o app confortavelmente pelo celular na mesma rede Wi-Fi,
**so that** o app pareça e se comporte como um aplicativo de verdade, não uma coleção de páginas soltas — fechando o MVP descrito no plano.

## Acceptance Criteria

1. `src/components/bottom-nav.tsx`: barra de navegação inferior fixa, **mobile-only** (`md:hidden`), com 5 links — Dashboard (`/dashboard`), Cartões (`/cards`), Compras (`/purchases`), Fixos (`/fixed-expenses`), Simular (`/simulate`) — cada um com ícone (`lucide-react`) + rótulo curto, destacando visualmente o link ativo (comparando `usePathname()` com o `href`). Padding inferior com `env(safe-area-inset-bottom)` (notch/gesture bar do celular).
2. `src/components/sidebar-nav.tsx`: sidebar fixa, **desktop-only** (`hidden md:flex`), com os mesmos 5 links do `bottom-nav.tsx` **mais** um link pra "Câmbio" (`/settings/currencies`) — a sidebar tem espaço pra um item a mais que a bottom-nav do mobile, então isso não contradiz a lista de 5 itens do plano (que descreve especificamente a nav mobile).
3. `src/components/app-shell.tsx`: compõe `bottom-nav.tsx` + `sidebar-nav.tsx` + um wrapper de conteúdo centralizado (`max-w-2xl mx-auto`), substituindo a formatação `max-w-*` que hoje está duplicada em cada `page.tsx`. Montado em `src/app/(app)/layout.tsx`, envolvendo `{children}` (junto com o `QuickAddFab` que já existe ali desde a Story 1.5).
4. `src/components/currency-input.tsx` ganha **máscara de separador de milhar** automática ao digitar (ex. `1234567` no valor bruto exibe `12.345,67` conforme o usuário digita) — mantendo intacta a lógica de parse já validada nas Stories 1.3/1.4 (`parseToCents`/`onBlur`), sem quebrar nenhum dos usos existentes do componente (cartões, compras, gastos fixos, lançamento rápido, simulação).
5. Adiciona `sonner` como dependência + `src/components/ui/sonner.tsx` (wrapper padrão shadcn/ui do `Toaster`, tema-aware — claro/escuro) + monta `<Toaster />` uma vez no layout raiz do app (`src/app/layout.tsx`).
6. As principais ações de mutação já existentes (criar cartão, criar compra — form completo e lançamento rápido —, criar gasto fixo, marcar parcela como paga/pendente, desativar cartão/gasto fixo, atualizar taxa de câmbio manual/API, confirmar simulação) passam a mostrar `toast.success("...")` em caso de sucesso, complementando (não substituindo) as mensagens de erro inline já existentes (`serverError`) — que continuam lá por acessibilidade e por já estarem testadas.
7. Nenhuma migration nova; nenhuma outra dependência nova além de `sonner`; todas as páginas/fluxos das Stories 1.1–1.9 continuam funcionando (esta story não altera nenhuma lógica de negócio, só a camada visual/navegação).

### Completion Notes List

- **`parseToCents` precisou de ajuste real, não só reuso** (diferente do que a Dev Notes original sugeria): a heurística antiga de "separador decimal = o último `,` ou `.` que aparecer" quebrava assim que a máscara passou a inserir múltiplos pontos de milhar (ex. `"1.234.567"` sem vírgula seria lido como `1234.567`, errado). Troquei pela heurística: vírgula presente → sempre decimal; só um ponto e no máximo 2 dígitos depois (sem vírgula) → também decimal (preserva colar `"1500.00"` em formato US); qualquer outro padrão de ponto(s) → milhar, descartado. Validado com script (`scripts/tmp-test-mask.ts`, removido depois): digitação incremental dígito a dígito, paste US, paste BR, valor vazio, round-trip — todos corretos.
- **Descoberta durante a implementação, corrigida antes de reportar como pronta**: `ensureRollingInstallments()` (Story 1.6) chamava `revalidatePath()` durante o render de `/dashboard` (Story 1.8), o que o Next 16 não permite ("used revalidatePath during render"). Reportado pelo usuário em produção local, corrigido em commit separado antes desta story (removida a chamada, já que a função não precisa revalidar nada — quem a chama já busca dados frescos na sequência). Mencionado aqui só como contexto, não é parte do escopo desta story.
- **`max-w-2xl` duplicado removido de 5 páginas de listagem/detalhe** (`/dashboard`, `/cards`, `/purchases`, `/fixed-expenses`, `/settings/currencies`), mas **os `max-w-sm` dos formulários foram mantidos deliberadamente** — são mais estreitos que o `max-w-2xl` do `AppShell` e aninham sem nenhum problema (CSS `max-width` aninhado sempre respeita o mais restritivo), representando uma escolha visual real (form mais compacto que lista), não uma duplicação. Achei que remover isso teria alargado todos os formulários desnecessariamente, contrariando a intenção original das Stories 1.3/1.4.
- **Toasts adicionados nas 7 mutações mais visíveis** (criar cartão, arquivar cartão, criar compra — 3 pontos de entrada: form completo, lançamento rápido, confirmação de simulação —, criar gasto fixo, desativar gasto fixo, atualizar/editar taxa de câmbio) — **deliberadamente sem toast** em marcar parcela como paga/pendente (frequente demais, o próprio botão já muda de texto/cor como feedback), conforme a própria Dev Notes já havia sugerido avaliar.
- **Sem `next-themes` no projeto**: `ui/sonner.tsx` usa `theme="light"` fixo, já que o app não tem alternância de tema (só o esquema `oklch` monocromático fixo em `globals.css`).
- **`npm run build` e `npm run lint` limpos** (0 erros, 0 warnings; mesmo warning conhecido de `middleware.ts`).
- **Validação manual sem navegador, ainda mais limitada que nas stories anteriores**: esta story é majoritariamente visual (nav mobile/desktop, máscara, toasts), então build/lint/scripts confirmam que o código não quebra, mas **não substituem** ver a interface de verdade.
