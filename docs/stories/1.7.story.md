## Story

**As a** usuário logado (eu ou minha namorada),
**I want** ver e atualizar a taxa de câmbio de cada moeda suportada (EUR, USD) pra BRL — buscando automaticamente de uma API gratuita ou cadastrando manualmente quando estiver offline ou quiser um valor específico,
**so that** o app tenha uma taxa confiável e atualizável pra calcular, mais adiante (Dashboard), um total combinado aproximado em BRL sem depender de uma chave paga.

## Acceptance Criteria

1. `src/lib/money.ts` exporta `convertToBRL(cents: number, rateToBRL: number): number`: converte um valor em centavos de uma moeda estrangeira pra centavos equivalentes em BRL (`Math.round(cents * rateToBRL)`). BRL nunca tem registro em `ExchangeRate` — sua taxa é implicitamente `1` e não passa por essa função nos usos futuros (Dashboard, Story 1.8).
2. `src/lib/validation/schemas.ts` exporta `exchangeRateSchema`: `currency` (enum das moedas de `SUPPORTED_CURRENCIES` **exceto BRL**), `rateToBRL` (number positivo — não é inteiro, câmbio é fracionário).
3. `src/lib/actions/exchange-rate-actions.ts` exporta `updateExchangeRateManually(input)`: `requireUser()`, valida com `exchangeRateSchema`, faz `upsert` do `ExchangeRate` (por `currency`) com `source="manual"` (o `updatedAt` é atualizado automaticamente pelo `@updatedAt` do Prisma).
4. `src/lib/actions/exchange-rate-actions.ts` exporta `fetchExchangeRateFromApi(currency)`: `requireUser()`, valida que `currency` é suportada e diferente de BRL, chama a **Frankfurter API** (`https://api.frankfurter.dev/v1/latest?base={currency}&symbols=BRL`, sem API key) num `try/catch`; em sucesso, faz `upsert` do `ExchangeRate` com a taxa retornada e `source="api"`; em falha (rede offline, resposta não-OK, JSON inesperado), **retorna um erro sem alterar o registro existente** — a última taxa salva (manual ou de API) permanece intacta.
5. `/settings/currencies` (`src/app/(app)/settings/currencies/page.tsx`): lista todas as moedas de `SUPPORTED_CURRENCIES` **exceto BRL**, mostrando pra cada uma: a taxa atual (se existir um `ExchangeRate` cadastrado, senão "não cadastrada"), a origem (`"manual"` ou `"api"`) e a data da última atualização (`updatedAt`, formatada). BRL aparece na lista apenas como referência informativa (taxa implícita = 1), sem controles de edição.
6. Cada moeda (exceto BRL) tem: um botão "Atualizar via API" que chama `fetchExchangeRateFromApi(currency)` e mostra o erro **de forma visível** se falhar, sem remover a taxa anterior da tela; e um campo/formulário de edição manual que chama `updateExchangeRateManually()`.
7. Validação (cliente e servidor): `rateToBRL` deve ser um número positivo (`> 0`); `currency` deve ser um código de `SUPPORTED_CURRENCIES` diferente de `"BRL"` — tentar editar a taxa de BRL é bloqueado tanto na UI (sem controles) quanto no schema (BRL fora do enum aceito).

### Frankfurter API

- Gratuita, sem API key, taxas do BCE (Banco Central Europeu). Endpoint: `GET https://api.frankfurter.dev/v1/latest?base={currency}&symbols=BRL`.
- Resposta esperada: `{ "amount": 1, "base": "EUR", "date": "...", "rates": { "BRL": 6.xx } }` — o valor em `rates.BRL` é exatamente o `rateToBRL` a salvar.
- **Tratar falha de rede/offline explicitamente**: `fetch()` pode rejeitar a Promise (offline) ou resolver com `response.ok === false` (erro HTTP) ou devolver um JSON sem a chave `rates.BRL` esperada — todos esses casos devem cair em `{ error: "..." }` sem escrever no banco, conforme a AC 4/6.

### Constante de escopo: `convertToBRL` vs. `userShareCents`

O comentário em `lib/money.ts` (deixado desde a Story 1.4) menciona os dois juntos como "Stories 1.6/1.7", mas isso ficou desatualizado com a ordem real do plano: `userShareCents` (split 50/50) é lógica do **Dashboard** (Story 1.8, onde o split é efetivamente exibido/somado), não desta story. Esta story adiciona **só** `convertToBRL`. Corrigir o comentário faz parte da Task 1.
