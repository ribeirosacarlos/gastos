## Story

**As a** desenvolvedor único do projeto,
**I want** ter o projeto Next.js inicializado com todas as dependências base (Tailwind, shadcn/ui, Prisma, iron-session, bcryptjs, zod, react-hook-form, date-fns, lucide-react) instaladas e configuradas,
**so that** eu tenha uma fundação funcional pronta para implementar o schema do banco, autenticação e as demais features do app nas próximas stories.

## Acceptance Criteria

1. Projeto Next.js 14+ criado com App Router e TypeScript via `create-next-app`.
2. Tailwind CSS configurado e funcional (classes utilitárias aplicam estilo na página inicial).
3. shadcn/ui inicializado, com os componentes base do plano instalados: `dialog`, `sheet`, `tabs`, `progress`, `badge`.
4. Prisma instalado e inicializado com datasource SQLite (`prisma/schema.prisma` criado, ainda sem models — isso é escopo da Story 1.2).
5. Dependências restantes instaladas: `iron-session`, `bcryptjs` (+ `@types/bcryptjs`), `zod`, `react-hook-form`, `date-fns`, `lucide-react`.
6. `npm run dev` inicia o servidor sem erros e a página inicial renderiza no navegador.
7. Estrutura de pastas base criada conforme a seção "Estrutura da aplicação" do plano: `src/app/`, `src/components/`, `src/lib/` (mesmo que com placeholders).

## Tasks / Subtasks

- [ ] Task 1: Criar o projeto Next.js (AC: 1)
  - [ ] Confirmar Node.js 18+ instalado (`node --version`)
  - [ ] Rodar `npx create-next-app@latest . --typescript --app --tailwind --eslint` na raiz do repositório
- [ ] Task 2: Configurar Tailwind + shadcn/ui (AC: 2, 3)
  - [ ] Validar que o Tailwind já veio configurado pelo `create-next-app` (globals.css, tailwind.config)
  - [ ] Rodar `npx shadcn@latest init`
  - [ ] Instalar os componentes: `npx shadcn@latest add dialog sheet tabs progress badge`
- [ ] Task 3: Instalar e inicializar Prisma (AC: 4)
  - [ ] `npm install prisma @prisma/client`
  - [ ] `npx prisma init --datasource-provider sqlite`
  - [ ] Confirmar `prisma/schema.prisma` criado com `provider = "sqlite"`
- [ ] Task 4: Instalar dependências restantes (AC: 5)
  - [ ] `npm install iron-session bcryptjs zod react-hook-form date-fns lucide-react`
  - [ ] `npm install -D @types/bcryptjs`
- [ ] Task 5: Criar estrutura de pastas base (AC: 7)
  - [ ] Criar `src/components/` e `src/lib/` (mesmo vazios, com `.gitkeep` se necessário)
- [ ] Task 6: Validar o boot da aplicação (AC: 6)
  - [ ] Rodar `npm run dev` e confirmar que a página inicial carrega sem erro no console

## Dev Notes

### Contexto (do plano aprovado)

- Stack: Next.js 14+ (App Router, TypeScript), Server Actions para mutações (sem `/api` separada, exceto `api/auth/logout/route.ts` em story futura). [Fonte: plano#Stack e bibliotecas]
- Banco: SQLite local via Prisma. Nesta story, apenas `prisma init` — os models (`User`, `Card`, `Purchase`, etc.) e a migration inicial ficam para a Story 1.2 ("Schema + seed + auth"). [Fonte: plano#Ordem de construção, passo 2]
- Estilo: Tailwind CSS + shadcn/ui, visual mobile-first. Componentes shadcn necessários nesta fase: Dialog, Sheet, Tabs, Progress, Badge (usados depois em `quick-add-sheet.tsx`, navegação, barra de limite, etc.). [Fonte: plano#Stack e bibliotecas]
- Multi-moeda e lançamento rápido (FAB) são requisitos do produto, mas **não fazem parte desta story** — entram no schema/UI a partir da Story 1.2 em diante. [Fonte: plano#Contexto]

### Estrutura de pastas esperada ao final desta story

```
gastos/
  prisma/schema.prisma          -- criado pelo `prisma init`, ainda sem models
  src/
    app/                        -- criado pelo create-next-app
    components/                 -- criar vazio (populado nas próximas stories)
    lib/                        -- criar vazio (db.ts, session.ts, etc. vêm na Story 1.2)
```
[Fonte: plano#Estrutura da aplicação]

### Notas de alinhamento de estrutura de projeto

Não existe `docs/architecture/unified-project-structure.md` neste projeto (é greenfield pessoal, sem arquitetura formal sharded). A referência de estrutura usada é a seção "Estrutura da aplicação" do plano aprovado, citada acima.

### Testing

- Não há testes automatizados nesta story — é puro scaffold. A validação é manual: `npm run dev` sobe sem erro (AC 6).
- Testes unitários (ex. vitest) para lógica financeira (`lib/money.ts`, `lib/dates.ts`) foram recomendados durante a revisão do plano, mas ficam para quando essas funções forem implementadas (Story 1.4 em diante, conforme a "Ordem de construção" do plano). Nenhuma ação necessária aqui.
