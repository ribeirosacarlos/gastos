## Story

**As a** desenvolvedor único do projeto,
**I want** ter o projeto Next.js inicializado com todas as dependências base (Tailwind, shadcn/ui, Prisma, iron-session, bcryptjs, zod, react-hook-form, date-fns, lucide-react) instaladas e configuradas,
**so that** eu tenha uma fundação funcional pronta para implementar o schema do banco, autenticação e as demais features do app nas próximas stories.

## Acceptance Criteria

1. Projeto Next.js 14+ criado com App Router e TypeScript via `create-next-app`.
2. Tailwind CSS configurado e funcional (classes utilitárias aplicam estilo na página inicial).
3. shadcn/ui inicializado, com os componentes base do plano instalados: `dialog`, `sheet`, `tabs`, `progress`, `badge`.
4. Prisma instalado e inicializado com datasource SQLite (`prisma/schema.prisma` criado, ainda sem models — isso é escopo da Story 1.2).
5. Dependências restantes instaladas: `iron-session`, `bcryptjs` (+ `@types/bcryptjs`), `zod`, `react-hook-form`, `date-fns`, `lucide-react`.
6. `npm run dev` inicia o servidor sem erros e a página inicial renderiza no navegador.
7. Estrutura de pastas base criada conforme a seção "Estrutura da aplicação" do plano: `src/app/`, `src/components/`, `src/lib/` (mesmo que com placeholders).

## Dev Notes

### Contexto (do plano aprovado)

- Stack: Next.js 14+ (App Router, TypeScript), Server Actions para mutações (sem `/api` separada, exceto `api/auth/logout/route.ts` em story futura). [Fonte: plano#Stack e bibliotecas]
- Banco: SQLite local via Prisma. Nesta story, apenas `prisma init` — os models (`User`, `Card`, `Purchase`, etc.) e a migration inicial ficam para a Story 1.2 ("Schema + seed + auth"). [Fonte: plano#Ordem de construção, passo 2]
- Estilo: Tailwind CSS + shadcn/ui, visual mobile-first. Componentes shadcn necessários nesta fase: Dialog, Sheet, Tabs, Progress, Badge (usados depois em `quick-add-sheet.tsx`, navegação, barra de limite, etc.). [Fonte: plano#Stack e bibliotecas]
- Multi-moeda e lançamento rápido (FAB) são requisitos do produto, mas **não fazem parte desta story** — entram no schema/UI a partir da Story 1.2 em diante. [Fonte: plano#Contexto]

### Completion Notes List

- `create-next-app` recusou rodar direto na raiz do projeto (conflito com `.aios-core/`, `.env`, `README.md`, etc. já existentes). Contornado gerando o scaffold em uma pasta temporária vazia e copiando só os artefatos do Next.js (`src/`, `public/`, configs, `package.json`) para a raiz, sem tocar em `AGENTS.md`, `README.md` ou `.gitignore` já existentes.
- `prisma init` (versão atual) gera `prisma.config.ts` (em vez de só `.env`) e instala pastas de "skills" para IDEs de IA (`.claude/skills/`, `.windsurf/`, `.agents/`) como efeito colateral — mantidas, são apenas documentação de referência do Prisma, não conflitam com nada do AIOS. `DATABASE_URL` já foi adicionado automaticamente ao `.env` existente.
- `src/components/` e `src/lib/` (Task 5 / AC 7) já existiam como efeito colateral do `shadcn init` (Task 2) — nenhuma ação extra necessária.
- `next dev` anexou um bloco `<!-- BEGIN:nextjs-agent-rules -->` ao `AGENTS.md` (comportamento nativo do Next 16, regenerado a cada `next dev`). Mantido conforme a própria recomendação do Next.js — não conflita com os blocos `AIOS-MANAGED` existentes.
- **Desvio do escopo original:** o `eslint.config.mjs` gerado pelo `create-next-app` lintava o repositório inteiro, incluindo `.aios-core/`, `.claude/`, etc. (scripts CommonJS legítimos que usam `require()`), gerando ~1800 erros falsos-positivos. Adicionei ignores para essas pastas de framework/tooling em `globalIgnores`, já que não fazem parte do app Next.js. Não estava listado como task explícita na story, mas era necessário para `npm run lint` passar (critério do DoD).
- `npm run lint` e `npm run build` rodados manualmente e confirmados limpos (ver seção Testing/DoD).
