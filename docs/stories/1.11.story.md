# Story 1.11: Cor do cartão + gráfico do dashboard por cartão

## Status

Ready for Review

## Origem

> Story fora da "Ordem de construção" original do plano — pedida diretamente pelo usuário após testar o MVP completo (Stories 1.1–1.10). Objetivo: diferenciar cartões visualmente por cor, e usar essas cores no gráfico do dashboard (Story 1.8, `month-timeline-chart.tsx`) pra mostrar a contribuição de cada cartão em cada mês, em vez do breakdown genérico "Parcelado vs. Fixo" atual. Escopo confirmado com o usuário antes da criação: seletor de cor livre (`<input type="color">`, não paleta fixa) e gastos fixos aparecem como um segmento cinza neutro separado no gráfico (não têm cartão, então não têm cor própria).

## Story

**As a** usuário logado (eu ou minha namorada),
**I want** escolher uma cor pra cada cartão e ver o gráfico do dashboard usando essas cores pra mostrar quanto cada cartão representa em cada mês (com gastos fixos num segmento cinza separado),
**so that** eu identifique rapidamente, olhando o gráfico, qual cartão está pesando mais em cada mês — sem precisar abrir cada cartão pra saber.

## Acceptance Criteria

1. `prisma/schema.prisma`: model `Card` ganha o campo `color String @default("#64748b")` (hex de 6 dígitos, cor neutra como default — inclusive pros cartões já existentes, que recebem esse valor pela migration). Nova migration criada e aplicada (`npx prisma migrate dev`).
2. `src/lib/validation/schemas.ts`: `cardSchema` ganha `color: z.string().regex(/^#[0-9a-fA-F]{6}$/, "Cor inválida")`.
3. `/cards/new`: novo campo de cor usando `<input type="color">` (seletor nativo do navegador, sem paleta fixa nem lib nova), default `#64748b`, vinculado ao campo `color` do form.
4. `createCard()` (`card-actions.ts`) não precisa de mudança de lógica — `color` passa a fazer parte de `parsed.data` (já espalhado direto pro `db.card.create`).
5. `/cards` (listagem) e `/cards/[id]` (detalhe): mostram um pequeno indicador circular da cor do cartão (`background-color: card.color`) ao lado do nome, além do texto já existente (cor nunca é o único jeito de identificar o cartão — o nome continua sempre visível).
6. `src/lib/actions/dashboard-actions.ts`: `getMonthlyTimeline()` passa a incluir, em cada mês retornado, um breakdown adicional **por cartão**: `byCard: Record<cardId, cents>` (aplicando `userShareCents`, mesma regra de sempre — só sobre `PurchaseInstallment`, já que `FixedExpenseInstallment` não tem cartão).
7. `src/lib/actions/dashboard-actions.ts` exporta `getActiveCardColors()`: retorna `{ id, name, color }[]` dos cartões ativos do usuário logado, pra montar a legenda/cores do gráfico sem duplicar essa busca em outro lugar.
8. `src/components/month-timeline-chart.tsx` reformulado: cada barra mensal passa a ter **N+1 segmentos empilhados** — um por cartão ativo (cor = `card.color`, convertido pra BRL) **mais** um segmento cinza neutro fixo pra "Fixos" (gastos sem cartão) — em vez do esquema atual de 2 tons de cinza (Parcelado/Fixo). Segmentos com valor zero num mês não são renderizados (sem barra de altura 0 poluindo visualmente).
9. Legenda abaixo do gráfico: um item por cartão (swatch da cor + nome) + um item "Fixos" (swatch cinza), cada um mostrando a **porcentagem que representa do total do período exibido** (não por mês individual — evita números ilegíveis em segmentos minúsculos). Identidade nunca só por cor: nome/rótulo sempre visível ao lado do swatch.
10. Tooltip (`title` nativo em cada segmento, mesmo padrão já usado no gráfico) mostra cartão/fixo + valor daquele mês específico + mês/ano.
11. Validação: nenhuma dependência nova; única mudança de schema é o campo `color` (migration simples, com default pros registros existentes); `/simulate`, `/purchases/new`, lançamento rápido continuam funcionando sem exigir `color` no formulário deles (campo é só do cartão).

## Dev Notes

### Previous Story Insights

- Story 1.8 (`dashboard-actions.ts`, `month-timeline-chart.tsx`) é a base direta desta story — `getMonthlyTimeline()`, `getCombinedBRLTotal()`, `userShareCents`, `convertToBRL` já existem e devem ser reaproveitados, não recriados.
- **Bug corrigido na Story 1.8** (registrado no Change Log dela): o container de cada coluna do gráfico precisa de `h-full` explícito, senão a altura em `%` das barras colapsa a 0 (CSS: `%` de altura só funciona com container de altura definida). Ao reformular o componente nesta story, **manter essa correção** — não é opcional.
- `Card.currency` é `String` livre (não enum), mesmo padrão a seguir pra `color` — string livre, validada por regex na aplicação, sem enum do Prisma.
- Não existe tela de edição de cartão ainda (Story 1.3 só fez criar/listar/detalhe/arquivar) — esta story adiciona `color` **só no formulário de criação**. Cartões já existentes ficam com a cor default até o usuário recriar ou até uma futura story de edição (fora de escopo aqui).

### Sobre a legenda mostrar percentual do período, não por mês

Um gráfico de barras empilhadas com N cartões + fixos, ao longo de 6 meses, teria segmentos pequenos demais pra rotular individualmente com número sem poluir visualmente (violaria a diretriz de "rótulo direto seletivo", não "um número em cada ponto"). A legenda abaixo do gráfico, com o percentual agregado do período inteiro por cartão, é a forma legível de comunicar "quanto cada cartão pesa" — o tooltip (`title`) cobre o detalhe por mês individual pra quem quiser passar o mouse/tocar.

### Testing

- Sem infraestrutura de testes automatizados no projeto ainda. O "teste principal" desta story é conferir que a soma dos segmentos por cartão + o segmento "Fixos" de um mês bate exatamente com `myTotals` daquele mês (já convertido pra BRL) — se não bater, a barra empilhada vai parecer "incompleta" ou "sobrando" visualmente. Validar via script antes de mexer no componente visual, mesmo padrão rigoroso das stories de lógica de agregação (1.6, 1.8, 1.9).
